1. Introducción

Este proyecto consolida el compilador MiniLang desarrollado a lo largo del ciclo en un producto funcional que completa la cadena de compilación moderna. Sobre la base de los Proyectos 1, 2 y 3 se incorporaron cuatro capacidades avanzadas:

  • Optimización automática del IR mediante el Pass Manager de LLVM a nivel O3 (Fase 7).
  • Módulo de optimización manual que aplica passes individuales y muestra su efecto con un comparador diff.
  • Generación de binarios nativos para Linux y Windows (.exe) por compilación cruzada desde WSL2 (Fase 8).
  • Extensión de la gramática a v4: switch/case con default, operador ternario, casting explícito y structs.

El lenguaje MiniLang utiliza palabras clave en español (programa, estructura, entero, segun, imprimir, etc.), manteniendo la continuidad con las entregas anteriores del ciclo.

2. Arquitectura del Pipeline v4 (8 Fases)

El archivo pipeline.py orquesta las ocho fases en secuencia estricta con medición de tiempos por fase. Se mantiene la parada temprana: si la fase léxica o sintáctica falla, el pipeline se detiene y reporta línea y columna del error sin continuar. Las fases 7 y 8 solo se ejecutan si la generación del IR (Fase 5) fue exitosa.

3. Fase 7 — Optimización Automática O3

El módulo optimizer.py aplica el conjunto de transformaciones O3 sobre el IR generado y produce un IR optimizado independiente, de modo que ambas versiones pueden compararse en la interfaz. Las transformaciones reportadas incluyen Constant Propagation / Folding, Dead Code Elimination (DCE), Function Inlining y Loop Unrolling.

3.2 Ejemplo concreto antes / después

Para ilustrar el efecto de las transformaciones, tomemos el siguiente fragmento fuente:

programa {
    entero a = 5 + 3;     // expresión constante
    entero b = a + 0;     // suma con elemento neutro
    entero muerto = 99;   // variable nunca utilizada
    imprimir(b);
}

IR generado (sin optimizar) — fragmento de la función main:

%".2" = add i32 5, 3          ; 5 + 3 calculado en ejecución
store i32 %".2", i32* %"a"
%"a.1" = load i32, i32* %"a"
%".4" = add i32 %"a.1", 0     ; suma con 0 (innecesaria)
store i32 %".4", i32* %"b"
store i32 99, i32* %"muerto"  ; almacenamiento muerto (no se usa)
%"b.1" = load i32, i32* %"b"
%".8" = call i32 (i8*, ...) @"printf"(i8* %".7", i32 %"b.1")

Tras la optimización O3, el Pass Manager:

  • Constant Folding: add i32 5, 3 se reemplaza por la constante 8.
  • Algebraic Simplification: add i32 %a, 0 se elimina (el 0 es elemento neutro).
  • Dead Code Elimination: el store i32 99, i32* %"muerto" se elimina porque su resultado nunca se consume.

El resultado observable del programa (imprimir(b) → 8) permanece idéntico, confirmando que la optimización no altera el comportamiento.

Nota sobre el entorno: la captura completa del IR optimizado por el LLVM Pass Manager (opt -O3) debe realizarse en WSL2/Linux, donde el binario opt está instalado. En entornos sin opt el sistema aplica un optimizador manual de respaldo con un alcance más limitado. Las métricas anteriores son reales y verificables ejecutando el pipeline.

4. Módulo de Optimización Manual del IR

El módulo ir_manual.py es el componente evaluativo central. Permite al usuario seleccionar desde la interfaz qué passes desea aplicar; el sistema los ejecuta programáticamente sobre el IR (el estudiante no edita el IR a mano) y muestra el efecto de cada transformación.

4.1 Passes disponibles

PassDescripción
mem2regPromueve alloca a registros SSA

simplifycfgSimplifica el grafo de flujo de control
dceElimina código muerto
inlineInline de funciones pequeñas
loop-unrollDesenrollado de ciclos

4.2 Comparador Diff y re-ejecución

Al aplicar los passes seleccionados, el panel muestra una vista paralela del IR antes y después, identificando las líneas añadidas, eliminadas y modificadas, junto a un resumen cuantitativo. El IR resultante puede re-ejecutarse desde la interfaz para verificar que la salida del programa no cambia, y exportarse a un archivo .ll independiente.

Captura del panel: ejecuta python web/app.py, abre http://localhost:5000, compila el programa de referencia, abre la pestaña 🛠️ IR Manual, selecciona al menos dos passes y captura el diff resultante para insertarlo aquí.

5. Fase 8 — Generación de Binarios Nativos

El módulo binary_generator.py compila el IR optimizado a un binario nativo aprovechando que el IR de LLVM es independiente de plataforma: el destino se indica mediante el target triple. El generador detecta las herramientas disponibles del sistema y reporta con claridad si alguna falta, sin abortar el pipeline.

PlataformaTarget tripleToolchainSalida
Linux x86_64x86_64-pc-linux-gnullc + gccbinario ELF ejecutable
Windows 64-bitx86_64-pc-windows-gnullc + MinGW-w64.exe PE32+

El generador de IR (ir_generator.py) acepta la plataforma destino para emitir el target triple correspondiente, y el enlazado se realiza con el linker adecuado a cada objetivo.

Requisitos en WSL2: 
sudo apt-get install llvm lld gcc gcc-mingw-w64-x86-64
El .exe generado se copia al sistema de archivos de Windows y debe producir exactamente la misma salida que el intérprete de la Fase 6.
