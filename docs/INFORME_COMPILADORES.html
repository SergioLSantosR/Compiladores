1. Resumen ejecutivo

Este documento describe el estado del proyecto MiniLang en el repositorio Compiladores: un front-end con ANTLR4 y Python que implementa un pipeline secuencial (lectura del fuente → léxico → sintáctico → AST → semántica → interpretación), deteniéndose ante errores. El lenguaje incluye int y bool, if/else, while, funciones con return y llamadas, y print. Los errores léxico/sintáctico se formatean con listeners personalizados; la semántica valida tipos y ámbitos; el intérprete ejecuta el AST.

2. Objetivos

  • General: Pipeline completo con intérprete, alineado al enunciado Proyecto 2 Compiladores 2026.
  • Específicos: Orquestar pipeline.py; reportar errores con línea/columna; gramática con while, func, return; pila de tablas hash para ámbitos; pruebas y documentación.

Diagrama de flujo del pipeline

[Archivo fuente UTF-8] ↓ [Fase 1: Lexer + LexerErrorListener] ──errores──→ código salida 1 ↓ [Fase 2: Parser + ParserErrorListener] ──errores──→ código 1 ↓ [Fase 3: AstBuilder → AST] ↓ [Fase 4: SemanticVisitor] ──errores──→ código 2 ↓ [Fase 5: InterpreterVisitor] ──error ejecución──→ código 3 ↓ Salida estándar (print, estado variables) → código 0

6. Gramática ANTLR

Archivo grammar/MiniLang.g4. Generación con visitor y sin listener en el generador:

java -jar antlr-4.13.1-complete.jar -Dlanguage=Python3 -visitor -no-listener -o gen/grammar grammar/MiniLang.g4

7. Pipeline de compilación

El módulo src/pipeline.py ejecuta: lectura única del archivo → lexer → parser → AST → semántica → intérprete. Códigos de salida: 1 léxico/sintáctico, 2 semántico, 3 ejecución, 0 éxito.

8. Manejo de errores

src/custom_errors.py: formato léxico [Error Léxico] Línea L, Columna C: Símbolo no reconocido '…'; sintáctico [Error Sintáctico] …; semántico [Error Semántico] …. Columna en formato 1-based para el usuario.

9. Árbol de sintaxis abstracta (AST)

Nodos en ast_nodes.py; construcción en ast_builder.py (visitor ANTLR).

10. Análisis semántico y ámbitos

semantic_visitor.py valida sin ejecutar. Pila de tablas hash: list de dict (self.scopes). El enunciado menciona symbol_table.py; aquí la lógica está integrada en el visitor (posible refactor futuro).

11. Intérprete

interpreter_visitor.py: evalúa el AST, pila de entornos para variables, llamadas y recursión, print a consola.

12. Casos de prueba

Carpeta tests/: test_valido.ml, test_error_lexico.ml, test_error_sintactico.ml, test_error_semantico.ml. Script tests/run_tests.ps1.
